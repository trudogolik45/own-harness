# 02: Shell-инструмент с белым списком

Type: task
Status: resolved
Blocked by: none

**What to build:** агент может выполнить команду в рабочей директории (запустить тесты, линтер,
`git`) и увидеть вывод с кодом возврата. Команды из белого списка (`pytest`, `ruff`,
`git status`, `git diff`, `git log`) идут без вопросов. Любая другая команда проходит через хук
подтверждения «y/N». Вывод обрезается по лимиту, таймаут защищает от зависания.

- [x] Агент запускает `pytest` и получает stdout, stderr и код возврата
- [x] Команда вне белого списка без подтверждения не выполняется, модель получает «blocked by user»
- [x] Команда дольше таймаута прерывается с понятным сообщением
- [x] Белый список задаётся в одном месте и покрыт тестами

## Answer

Сделан инструмент `run_command`. Без вопроса идут только команды из белого списка с безопасными
флагами и путями внутри проекта. Такие команды запускаются без shell, по проверенным токенам.
Всё остальное и запись в `.git/` / `.venv/` подтверждается «y/N». Таймаут убивает всю группу
процессов. Вывод обрезается с сохранением начала и конца.

Принятый риск: модель может записать код в тест или конфиг и запустить его через `pytest`.
Это основной сценарий агента, он описан в README в разделе «Безопасность».

Три круга ревью: CRITICAL и HIGH закрыты. Тестов 79, `ruff` чистый.
