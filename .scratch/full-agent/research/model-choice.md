# Выбор локальной модели для агентного цикла (16 ГБ, M1 Pro)

Вопрос тикета 01: какая локальная модель в 16 ГБ надёжнее всего гоняет агентный цикл с инструментами.

## Методика

- Харнес из `src/harness/` без изменений; обёртка-счётчик над `OpenAICompatibleLLM` (скрипт во `/tmp`, удалён) считает ответы с нативными `tool_calls` и восстановленными `recover_tool_call` (`id == "recovered"`).
- Одна сессия, два хода в чистой папке:
  1. «Создай мини-приложение из 3 файлов: main.py, utils.py, test_utils.py. utils.py содержит функцию add(a,b). Сначала посмотри, что есть в директории.»
  2. «Теперь прочитай utils.py и добавь функцию sub(a,b).»
- Проверка по диску: 3 файла, `def add` и `def sub` в utils.py, `python3 -I -m py_compile` по каждому файлу.
- Ollama, OpenAI-совместимый эндпоинт, дефолтные параметры сэмплирования. Ограничение: у `qwen3:4b` первые два прогона шли во время скачивания других моделей, их время завышено; поэтому добавлены ещё два прогона на свободной машине.

## Результаты

| Модель | Прогонов | Задача выполнена | Нативные tool calls | Восстановленные | Ответов без вызова (финалы) | Итераций на сессию | Время, с |
|---|---|---|---|---|---|---|---|
| qwen3:4b | 4 | 4/4 | 25 (100%) | 0 | 8 | 6-9 | 185, 227, 309, 367 (идл.: 185, 309) |
| qwen3:8b | 4 | 3/4 (в одном прогоне нет test_utils.py, хотя модель заявила, что создала) | 23 (100%) | 0 | 8 | 7-8 | 143, 175, 182, 200 |
| qwen2.5-coder:14b | 2 | 0/2 | 0 | 1 | 4 | 2-3 | 21, 87 |

Детали qwen2.5-coder:14b: в прогоне 1 модель выдала текст `{"function": list_files, "arguments": ...}`: это невалидный JSON и другая схема (`function` вместо `name`), `recover_tool_call` его не подхватывает, цикл завершился на первой итерации. В прогоне 2 один вызов восстановлен, но на втором ходу модель снова писала JSON в markdown-обёртке с нумерацией, а не вызывала инструмент; ни одного файла не создано.

## Вывод

Модель по умолчанию: **qwen3:8b**.

- Обе qwen3 стабильно отдают нативные tool calls (100%, восстановление не понадобилось); qwen2.5-coder:14b в Ollama с харнесом инструменты не вызывает вовсе, несмотря на размер.
- qwen3:8b быстрее qwen3:4b на этой задаче (143-200 с против 185-367 с), вероятно, потому что 4b дольше «думает» и делает лишние итерации. Цена: в одном из четырёх прогонов 8b пропустила файл и сообщила, что создала все три; у 4b такого не было. Выборка мала (n=4), различие в надёжности статистически не доказано; для проверки результата стоит держать в харнесе верификацию по диску.
- Память: qwen3:8b (около 5 ГБ) комфортно помещается в 16 ГБ.
