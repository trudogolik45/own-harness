# own-harness

Минимальный харнес по формуле из видео «ИИ-Агент vs Харнесс» (Артём Шумейко):

- **LLM** — функция «текст на входе → текст на выходе» (`llm.py`).
- **Tools** — «руки» модели: `list_files`, `read_file`, `write_file`, `edit_file`, `search` (`tools.py`, поиск через `rg`) и `run_command` (`shell.py`).
  Без вопроса идут только команды из `ALLOWLIST` в `shell.py` с безопасными флагами и путями внутри проекта.
  Остальное, а также запись и правку в `.git/` и `.venv/`, харнес подтверждает «y/N» (`ShellPolicy`).
  Команду, которую никто не одобрил, `run_command` не выполнит.
- **Агентный цикл** — модель вызывает инструменты, пока не даст финальный ответ (`loop.py`).
  Свежий результат инструмента модель видит целиком (до `max_output_chars`), длинные результаты
  старых итераций заменяются заглушкой (`conversation.py`). Настройки — `keep_recent_iterations` и `stale_result_chars` в `Agent`.
  Если модель замолчала посреди задачи, харнес до `max_nudges` раз просит её продолжить.
- **Память** — `AGENTS.md` / `CLAUDE.md` подмешиваются в системный промпт (`memory.py`).
- **Хуки** — перехват событий цикла: лог итераций, подтверждение команд (`hooks.py`).
- **Агент = харнес + LLM** — всё собирается в `cli.py`.

## Запуск

Нужен любой OpenAI-совместимый сервер. Локально — Ollama:

```bash
brew install ollama ripgrep
ollama serve
ollama pull qwen3:8b
uv sync
uv run harness --root ./sandbox
```

Параметры (флаги или переменные окружения `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`):

| Флаг | По умолчанию |
|------|--------------|
| `--base-url` | `http://localhost:11434/v1` |
| `--model` | `qwen3:8b` |
| `--api-key` | `ollama` |
| `--root` | `.` — файловые инструменты не выходят за эту директорию |
| `--approve` | выключен — спрашивать «y/N» перед каждым инструментом |

Пример с OpenAI:

```bash
LLM_BASE_URL=https://api.openai.com/v1 LLM_MODEL=gpt-4.1-mini LLM_API_KEY=sk-... uv run harness
```

## Тесты

```bash
uv run pytest
```

## Особенность маленьких моделей

`qwen3:4b` иногда пишет вызов инструмента текстом в JSON вместо настоящего tool call.
Харнес ловит это в `recover_tool_call` и превращает в обычный вызов. Это и есть «умный харнес» из видео.

## Безопасность

Белый список — удобство, а не песочница. Модель может записать код в тест и запустить его
через `pytest` без вопроса. Конфиги проекта (`pyproject.toml`, `pytest.ini`, `ruff.toml`)
тоже управляют разрешёнными командами: модель может дописать туда опасные опции. Не запускай харнес на машине или в папке, которую жалко.
Нужен полный контроль — запускай с `--approve`.
